Project 18: penyebab rework apa yang paling sering? (simulasi)

Tujuan project: mengelompokkan catatan rework operator ke kategori penyebab, membuat Pareto dan tren, dan menilai seberapa bisa dipercaya klasifikasi otomatisnya. Data adalah simulasi; LLM tidak dipanggil.

Status: selesai (dashboard belum di-deploy)Manufaktur · teksDATA SIMULASISQL · Python · scikit-learn
DATA SIMULASI, TANPA LLM. Catatan rework dibangkitkan dari templat sederhana lalu dianonimkan. Rancangan memakai Claude API, tetapi project ini tidak memanggilnya (tidak ada API key); klasifikasi dijalankan oleh pengganti lokal. Akurasi tinggi di bawah mencerminkan teks sintetis yang mudah, bukan catatan nyata.

Pertanyaan
Penyebab rework apa yang paling sering muncul di catatan operator, bagaimana trennya per stasiun dan bulan, dan seberapa bisa dipercaya klasifikasi otomatisnya?
Data
Simulasi: 3.060 catatan mentah, 2.724 valid untuk klasifikasi, 5 stasiun, 9 kategori, Maret–Agustus 2026; golden set 269 catatan valid.
Temuan utama
Penyebab terbesar Perekat kurang / berlebih (27,3% catatan). Tiga kategori teratas hanya 64,0%; butuh 5 kategori untuk mencapai 80%, jadi Pareto 80/20 klasik tidak berlaku.
Keputusan yang didukung
Mulai perbaikan dari C4 dan stasiun yang menonjol; jangan fokus hanya pada satu atau dua penyebab. Menurunkan C4 sebesar 20% menghemat sekitar 5,0 jam rework per bulan perkiraan.
Metode
DuckDB + SQL (view Pareto dan tren), Python (pandas, scikit-learn, SciPy, statsmodels), chi-square dan binomial dengan koreksi Holm, p-chart bulanan, evaluasi klasifikasi (accuracy, macro F1, confusion matrix, kalibrasi).
Catatan jujur
Klasifikasi LLM tidak diuji; pengganti lokal mencapai accuracy 99,3% dan baseline kata kunci 100,0% karena teks sintetis. Hipotesis perbandingan LLM vs baseline belum bisa disimpulkan.

  • Cek silang SQL vs pandas: 397 dari 397 nilai cocok.
  • Cek silang SQL vs Excel (dihitung ulang dengan LibreOffice): 9 dari 9 kategori cocok.
  • Pemulihan fakta tertanam: 10 dari 10 sesuai.
  • Pemanggil API diuji dengan klien palsu: 8 dari 8 lulus (tidak memanggil Claude API sungguhan).

Batasan

  • Data simulasi, teks dari templat sederhana; angka terlalu optimistis dibanding catatan nyata.
  • Claude API tidak diuji: perbandingan LLM vs baseline, konsistensi dua kali jalan, dan biaya tidak terjawab. Label manual adalah kebenaran generator tanpa noise.
  • Hanya 2 kesalahan di golden set, jadi pertanyaan kategori mirip yang tertukar tidak bisa disimpulkan.
  • Ambang "sekitar 80%", rasio 1,5, batas 3 sigma, batas 3 kata, menit rework, dan detik baca adalah asumsi project.
  • Dashboard belum di-deploy; keterbacaan oleh orang awam belum diuji.
