Project 25: bisakah laporan Excel berantakan jadi tabel rapi tanpa copy-paste? (simulasi)

Tujuan project: mengubah laporan Excel manual berlayout bebas menjadi tabel tidy, membuktikan kebenarannya, dan membandingkan metode. Data adalah simulasi.

Status: selesai (dashboard belum di-deploy)Manufaktur · ExcelDATA SIMULASIPython · YAML · DuckDB · Excel
DATA SIMULASI. 36 file Excel dibangkitkan dari data rapi lalu dikotori dengan 6 layout dan sel bermasalah yang ditanam. Hasil membuktikan metode, bukan kondisi pabrik; laporan nyata lebih berantakan.

Pertanyaan
Bagaimana mengubah laporan Excel manual berlayout bebas menjadi tabel tidy tanpa copy-paste, membuktikan hasilnya benar, dan memilih metode yang cocok untuk tiap situasi?
Data
Simulasi: 36 file Excel, 6 layout, 54.000 nilai dengan kunci jawaban; 972 sel angka kotor, 2 subtotal salah ketik, 1 sheet ganda ditanam.
Temuan utama
Parser berbasis config menghasilkan 54.000 nilai; 53.520 dari 53.520 nilai berstatus ok/fixed sama persis dengan kunci (0 salah lolos), 480 nilai ditandai di log anomali. Kecocokan seluruhnya 99,1%.
Keputusan yang didukung
Pakai parser Python berbasis config untuk banyak file dan banyak layout; rumus Excel untuk satu-dua file. Hemat sekitar 36 jam kerja per tahun perkiraan.
Metode
Parser Python + YAML (pengenalan template dari isi sel), rekonsiliasi dengan subtotal, DuckDB + SQL, rumus Excel (LibreOffice), pytest dan uji skenario perubahan layout.
Catatan jujur
Power Query hanya ditulis, belum dijalankan (tidak ada Excel). Waktu pembuatan oleh manusia tidak diukur. Data lebih rapi daripada laporan nyata.

Rekomendasi dan dampakPerkiraan; asumsi dijelaskan di bawah

  • Rumus Excel: end user di lini produksi dengan satu atau dua file, tanpa programmer.
  • Power Query: tim non-programmer dengan banyak file satu layout (belum diuji).
  • Python (parser): banyak file dan banyak layout, perlu bukti kebenaran; berhenti bila layout tak dikenal.
  • SQL (DuckDB): data sudah berupa tabel di database.

VerifikasiPipeline dijalankan ulang dari nol; hasil sama dengan yang tersimpan

  • Cek silang SQL vs pandas: 18 dari 18 cocok; validasi 7 dari 7 lulus; pytest 35 dari 35 lulus.
  • Tabel hasil, akurasi, dan rekonsiliasi identik pada rerun; hanya angka waktu proses yang berubah.
  • Skenario perubahan layout: parser lama berhenti dengan aman pada semua skenario, lalu cocok penuh dengan config baru.

Batasan

  • Data simulasi yang lebih rapi dari laporan nyata. Dari 1.215 sel yang dicatat bermasalah, 240 jenis 'blank' ternyata tidak dikosongkan generator, jadi yang nyata 972 sel angka kotor.
  • Parser hanya seandal config-nya; layout yang berubah total tetap butuh config baru, struktur baru butuh kode pembaca baru.
  • Rekonsiliasi hanya pada layout dengan subtotal (layout 1 dan 2).
  • Power Query belum dijalankan; Excel dihitung dengan LibreOffice. Pembanding rekap copy-paste manual tidak dilakukan; dashboard belum di-deploy.
