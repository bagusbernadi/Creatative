Project 33: bisakah log Excel berantakan diubah otomatis jadi database bersih? (simulasi)

Tujuan project: membangun ETL yang membaca log Excel operator, memvalidasi, mengarantina baris bermasalah, dan memuat sisanya ke SQL. Data adalah simulasi.

Status: selesai di branch buildManufaktur · ETLDATA SIMULASIPython · DuckDB · SQL
DATA SIMULASI. Log Excel dibangkitkan (60 file, 7.260 baris) dengan 420 masalah yang sengaja ditanam; hasil membuktikan metode, bukan kondisi pabrik. Menit per langkah sebelum ETL adalah asumsi, bukan pengukuran.

Pertanyaan
Bagaimana mengubah log Excel operator yang berantakan menjadi data siap analisis, berapa baris yang bermasalah, dan berapa jam kerja yang bisa dihemat?
Data
Simulasi: 60 file Excel, 3 versi template, 10 stasiun, 3 model, Mar–Agu 2026; 7.260 baris data.
Temuan utama
ETL memuat 6.960 baris dan mengarantina 300 (4,1%) dalam 1,3 detik. 420 dari 420 masalah tertanam ditangani benar. Run kedua memuat 0 baris baru.
Keputusan yang didukung
Jadikan ETL jalur standar log Excel: baris bermasalah dikarantina dan dikoreksi manusia. Menyusun laporan turun dari 170 ke sekitar 8 menit; pada 8 laporan per bulan sekitar 259 jam per tahun perkiraan.
Metode
Python (pandas, openpyxl) dengan pemetaan kolom YAML, DuckDB + SQL (staging, karantina, view), pytest, cek silang pandas dan Excel (LibreOffice), dashboard Streamlit.
Catatan jujur
4 dari 5 fakta yang direncanakan hanya sebagian terwujud di data simulasi (mis. tidak ada angka serial Excel). Tidak ada baris data hilang, tetapi data adalah simulasi.

Rekomendasi dan dampak

  • Jadikan ETL ini jalur standar masuknya log Excel.
  • Karantina lalu koreksi manusia, jangan perbaiki diam-diam.
  • Template baru ditambah lewat column_mapping.yml tanpa mengubah kode.

VerifikasiPipeline dijalankan ulang dari nol; hasil sama kecuali angka durasi

  • Rekonsiliasi per file: 60 dari 60 lulus; cek silang pandas 10 dari 10; Excel (LibreOffice) 241 dari 241.
  • Uji run ulang dan koreksi karantina: 21 dari 21 lulus.
  • Durasi run dan waktu tunggu bergantung mesin: run ulang memberi 2,2 detik, bukan 1,3.

Batasan

  • Data simulasi: hasil membuktikan metode, log nyata bisa lebih beragam.
  • Menit per langkah sebelum ETL adalah asumsi, bukan pengukuran.
  • Cek silang Excel dihitung ulang oleh LibreOffice, bukan Microsoft Excel.
  • Dashboard belum di-deploy; workflow GitHub Actions ditulis tetapi belum terbukti jalan di GitHub.
