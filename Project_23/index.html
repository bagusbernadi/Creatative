Project 23: bisakah laporan KPI harian terkirim otomatis dengan alert yang tepat? (simulasi)

Tujuan project: mengirim ringkasan KPI harian dan alert ke Telegram otomatis, dengan alarm palsu seminimal mungkin. Data simulasi; bot dry-run, belum mengirim sungguhan.

Status: selesai (belum diuji ke Telegram sungguhan)Manufaktur · automasiDATA SIMULASIPython · DuckDB · Telegram (dry-run)
DATA SIMULASI, BOT DRY-RUN. Data produksi dibangkitkan; bot belum pernah mengirim ke Telegram sungguhan. Pengiriman diuji dengan transport palsu, dan kegagalan serta jeda run terjadwal adalah simulasi.

Pertanyaan
Bagaimana mengirim ringkasan KPI harian (yield, NG rate, rework rate per stasiun) beserta grafik ke Telegram secara otomatis, dengan alert yang menangkap masalah nyata tanpa terlalu banyak alarm palsu?
Data
Simulasi lini perakitan sepeda motor: 4.477 baris produksi mentah menjadi 4.440 bersih (111 baris kotor, semua ditemukan), 75 hari kerja; 3 penurunan yield, 2 hari data terlambat, 1 hari kosong ditanam.
Temuan utama
Aturan alert R1 dan R2 menangkap ketiga penurunan yield tanpa alarm palsu (3 dari 3 benar); ambang tetap 86,5% menghasilkan 5 alert palsu dan aturan "defect naik > 50%" 124 dari 143 alert palsu.
Keputusan yang didukung
Pakai R1 dan R2 sebagai alert utama, R3 sebagai informasi tambahan. Otomatisasi menghemat sekitar 114 jam kerja per tahun perkiraan.
Metode
Python + DuckDB + SQL, bot dengan dry-run, alert berbasis rata-rata bergulir 20 hari (σ dan Poisson), replay terhadap kejadian tertanam, cek silang bot vs SQL vs Excel (LibreOffice), pytest.
Catatan jujur
Evaluasi alert memakai 3 kejadian dan data yang sama dengan pemilihan parameter (in-sample). Penurunan perlahan di Dyno baru terdeteksi hari ke-5 dari 7 hari.

Batasan

  • Data simulasi; hasil membuktikan metode, bukan kondisi pabrik. Evaluasi alert in-sample pada 3 kejadian.
  • Bot belum mengirim ke Telegram sungguhan; TelegramSender diuji dengan transport palsu. Workflow GitHub Actions belum dijalankan; dashboard belum di-deploy.
  • Alert dicek sekali sehari, bukan real-time; alert menunjukkan kapan yield turun, bukan penyebabnya.
  • Waktu manual per laporan adalah estimasi; Excel dihitung ulang LibreOffice, bukan Microsoft Excel.
